Aislamiento Multi-Tenant en Kernel PostgreSQL 16 (FORCE RLS)

  • Cada empresa opera identificada por tenant_id bajo políticas ENABLE + FORCE ROW LEVEL SECURITY en PostgreSQL 16 (94 tablas operativas por tenant y 2 tablas raíz de cuentas).
  • La aplicación ejecuta en producción con el rol de mínimo privilegio calcu_app (sin permisos SUPERUSER ni BYPASSRLS).
  • En cada transacción se fija set_config('app.current_tenant', ..., true) con alcance local: ante ausencia de sesión o contexto válido, el motor falla cerrado (0 filas visibles).
  • El alcance administrativo global (app.is_superadmin) queda restringido únicamente a rutas explícitas del Plano de Control y nunca se habilita en rutas operativas.
Encrypt-then-MAC (CTR + HMAC-SHA256)

Bóveda Criptográfica 256-bit & Enmascarado CWE-312 / CWE-532

  • Las credenciales sensibles de conectores (SMTP/IMAP, Meta, Mercado Libre, WeTrade, Mercado Pago y wallets) se cifran en base de datos mediante flujo CTR de 256 bits con nonce aleatorio CSPRNG de 16 bytes y autenticación HMAC-SHA256 con claves separadas por dominio.
  • La detección de manipulación o corrupción de integridad aborta el descifrado antes de devolver ningún secreto.
  • Las respuestas API devuelven valores redactados (sanitize_credentials_for_response) y los logs rotativos filtran contraseñas, tokens Bearer/JWT, API keys y numeración financiera de 13–19 dígitos.
Sin cuentas genéricas ni contraseñas en claro

Identidad Zero-Trust, PBKDF2-HMAC-SHA256, 2FA TOTP & JWT JTI

  • Contraste de contraseñas mediante PBKDF2-HMAC-SHA256 con comparación en tiempo constante y bloqueo anti-fuerza bruta por IP tras 5 intentos fallidos.
  • Autenticación opcional de doble factor (2FA TOTP RFC 6238) y desafíos captcha firmados con HMAC sin rastreo de terceros.
  • Tokens JWT HS256 firmados con identificador único jti y revocación instantánea (Redis + memoria en proceso) al cerrar sesión o invalidar credenciales.
  • Cookies de sesión endurecidas con HttpOnly, Secure, SameSite=Strict y expiración acotada; cuentas genéricas (demo / anonymous) bloqueadas de raíz.
Consentimiento explícito del Tenant

Soporte Delegado Just-In-Time (JIT máx. 60 min) & Trazabilidad

  • La consola del operador SaaS (SuperAdmin UID-0001) está separada del espacio privado de cada cliente: el operador gestiona planes y licencias sin acceder a datos operativos del Tenant.
  • Para asistencia técnica dentro de un Tenant se requiere aprobación expresa del propietario de la cuenta mediante sesión temporal JIT de 5 a 60 minutos, revocable en cualquier momento.
  • Cada evento crítico y acceso JIT queda registrado con marca temporal en bitácora de auditoría.
Validación estricta de entrada y salida

Escudo Perimetral HTTP, Anti-XSS / CWE-89 / SSRF & Webhooks HMAC

  • Cabeceras HTTP defensivas: Strict-Transport-Security (HSTS preload), Content-Security-Policy estricta, X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN y Permissions-Policy.
  • Validación estricta de esquemas Pydantic con rechazo de campos no declarados (extra="forbid"), sanitización XSS y bloqueo semántico de inyecciones SQL multi-sentencia.
  • Control SSRF saliente por lista blanca exacta (allowlist de orígenes autorizados) con bloqueo de IPs privadas, loopback no autorizado y endpoints metadata cloud (169.254.169.254).
  • Webhooks externos críticos (Mercado Pago, Mercado Libre, WeTrade) verificados mediante firma criptográfica HMAC-SHA256 y protección anti-replay temporal/idempotente.
Transparencia de fuentes abiertas

Frontera Clara con Datos Públicos Estatales (RUPE / ARCE / SICE)

  • El módulo de Licitaciones y Compras Estatales (Plan 3) consulta registros abiertos publicados oficialmente por ARCE / SICE y RUPE en Uruguay.
  • La información pública estatal nunca se mezcla ni expone datos privados comerciales, contables o fiscales almacenados dentro de otros tenants de CalcuSuiteIA.
